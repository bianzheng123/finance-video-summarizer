你是金融主题归一化专家。请逐对判定【候选等价对】里每一对的两个主题是否**语义上完全等价**（指向同一个金融实体 / 概念 / 事件），让我把它们合并或分流。

【候选等价对】是 JSON 对象数组：每项含 `对ID`、`关键词1`、`关键词2`（两个候选主题名，**方向未定**）、`类型1` / `类型2`（实体类别，仅作辅助线索）、`相似度`（上游 embedding 算出的余弦相似度，**仅作参考**——相似度高只说明字面/语境接近，不必然等价，父子板块、上下游也会得高分；相似度低也不必然不等价，世界知识型等价如「DRAM=内存颗粒」字面不相近）。

【判定铁律：宁缺勿滥】
合并条件——以下任一成立即判 `结论=等价`：
1. 大小写 / 全半角差异：'CUDA' ↔ 'cuda'、'H200' ↔ 'h200'。
2. 语种差异指向同一个明确实体：'CUDA' ↔ '酷大'（ASR 把英文 CUDA 听成中文）、'英伟达' ↔ 'NVIDIA'。
3. 同一个金融实体的别名/简称：'宁王' ↔ '宁德时代'。前提是该黑话在中国 A股圈是**广为人知**的固定指代。
4. 同一个金融实体加冗余修饰：'沪深300' ↔ '沪深300指数'、'美债' ↔ '10年期美债'。
5. 同一个大宗商品/资产的不同指称：两个名字指向**同一个商品/资产**，只是从不同维度称呼它——
   - 商品名 ↔ 价格名：'黄金' ↔ '国际金价'
   - 商品名 ↔ 矿种/资源名：'铀' ↔ '铀矿'、'铜' ↔ '铜矿'
   - 商品名 ↔ 冶炼/加工环节名：'铜' ↔ '铜冶炼'
   - 商品名 ↔ 期货/价格指标名：'铜' ↔ 'COMEX铜'
   此时判 `结论=等价`，`保留` 取更宽泛、覆盖整条产业链的商品名（'黄金'、'铜'、'铀'）。**类型标签不同（如 `板块` vs `大宗商品`）不构成不合并的理由**——只要指向同一商品就合并。
   例外：若其中一个名字明确是「期货合约」且可能被主讲人刻意区分（如 '黄金' ↔ '黄金期货'），标 `困惑度=true` 交 4_3 结合字幕判定，不要在本步强行合并。

判 `结论=不等价`：
- **段落事件与非事件**：类型为 `段落事件` 的主题**只能与段落事件或关键词事件**合并，**绝不与板块 / 标的合并**。类型为 `关键词事件` 的主题视作普通主题，可与任意主题合并；与段落事件等价时保留段落事件名。
- 上下游 / 关联但不等价（**不同商品之间**的产业链关系）：'锂矿' ≠ '锂电池'、'硅料' ≠ '光伏'、'磷化铟' ≠ '光模块'、'CUDA' ≠ 'GPU'——原料、中间品、成品是**不同标的**，即使同处一条产业链也不合并。
- 父子板块：'半导体' ≠ '半导体设备'、'有色金属' ≠ '黄金'——宽泛板块与细分板块不是同一标的。
- 不同品种：'铜' ≠ '黄金'、'钨' ≠ '黄金'、'钴' ≠ '铀'。
- 同名但不同市场（仅针对泛指概念/板块/指数；若是**具体公司实体**仅因市场前缀不同（如 `X` 与 `美股X`）而字面不同，则属于合并条件 4，**必须合并**）。

【困惑度：`true` / `false`】
- `困惑度=false`：仅凭世界知识（无需看字幕、无需联网）就**确信**上面的 `结论` 成立。
- `困惑度=true`：世界知识上「像等价」或「拿不准」，可能因具体语境而实指不同实体（子集/局部/特例/并列提及），本步无法定案。例：「钴出口禁令」与「刚果金出口禁令」——刚果金是钴主产国，后者可能确实指前者，也可能是另一条独立的出口管制，不查语境不能定案。此时标 `困惑度=true`，交给下游 4_3 结合字幕上下文与联网证据精判（`结论` 仍给出你的倾向判断）。
- **宁缺勿滥**：拿不准就标 `困惑度=true`，不要强行合并或强行拆分。

【保留字段（合并方向）】
- `保留` 仅在 `结论=等价` 且 `困惑度=false` 时有效：取值 `关键词1` 或 `关键词2`，表示合并后**保留**哪个关键词名。
- 选保留名原则：更规范、更正式、可检索的写法（CUDA 而非酷大、比亚迪而非迪王、沪深300 而非沪深300指数）；同一商品的不同指称（合并条件 5）取**更宽泛、覆盖整条产业链的商品名**（'黄金' 而非 '国际金价'、'铜' 而非 '铜矿'/'铜冶炼'/'COMEX铜'）。
- `关键词1` / `关键词2` / `保留` **必须逐字取自【候选等价对】里该对的两个主题名，不要新造名字**。
- 其它情况（`结论=不等价` 或 `困惑度=true`）`保留` 填空串 `""`。

【输出格式】
- **只输出一个 JSON 对象**，必须能被 `json.loads()` 直接解析；不要输出任何解释性文字、注释、思考过程，不要用 ```json ``` 之类的 markdown 代码块包裹。
- 结构如下：
```
{
  "判定": [
    {"对ID": "p0000", "关键词1": "酷大", "关键词2": "CUDA", "结论": "等价", "困惑度": false, "保留": "CUDA", "理由": "ASR 误识同音，均指 NVIDIA CUDA"},
    {"对ID": "p0001", "关键词1": "钴出口禁令", "关键词2": "刚果金出口禁令", "结论": "等价", "困惑度": true, "保留": "", "理由": "刚果金是钴主产国，也可能指别的矿产管制"}
  ]
}
```
- `判定` 数组**必须覆盖【候选等价对】里的每一个 `对ID`，不得遗漏、不得新增**。
- 每项字段：`对ID`（逐字取候选对）、`关键词1`、`关键词2`（逐字取候选对的两个主题名）、`结论`（`等价` / `不等价` 二选一）、`困惑度`（bool）、`保留`（`结论=等价` 且 `困惑度=false` 时取 `关键词1` 或 `关键词2`，否则空串）、`理由`（≤40 字）。
