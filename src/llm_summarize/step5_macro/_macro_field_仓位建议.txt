【JSON 结构】（示例仅说明格式，请勿直接复制内容）
{
  "仓位建议": [
    {
      "标题": "≤15字，概括该条建议（如"仓位不宜低于5成"）",
      "观点": "主讲人明确或隐含的仓位/操作建议，只需点明建议及其核心依据，无需展开分析过程",
      "引用": [int, int, ...]
    }
  ]
}

【字段提取规则】
4. 仓位建议
   - 提取内容：主讲人对**总仓位/整体敞口**的建议——几成仓、加仓/减仓/调仓/观望、卸杠杆。判定标准是"这句话回答的是**手里总共该拿多少**"。
   - **作用域下界（硬约束，越界的条目会被系统删除）**：本字段只收**账户层面的总量建议**。以下三类都**不属于**本字段，一条都不要输出：
     * **单一标的/板块的买卖时机或持有周期**（"铀矿可以拿两三年"、"光和设备等调整到位再布局"、"紧盯某公司半年报"）→ 属于该标的/板块的投资机会，由其他阶段负责；
     * **通用交易纪律与方法论**（"年线之上不做空"、"散户不必提高日内水平"、"持有时间越长越不容易被割"）→ 属于交易技巧，由其他阶段负责。这类内容的特征是：**换任何一个标的、换任何一场行情都成立**，与本场当下该拿几成仓无关；
     * 纯行情判断（"大盘还要调整"）→ 属于宏观观点。
     判断口径就一句话：**如果这句建议里换掉标的名、或搬到下一场直播照样成立，它就不是本场的仓位建议。**
   - 分块要求：每条独立的总仓位建议一块（如"现在不宜低于5成"与"借机卸杠杆"分开成块）。
   - 「标题」：≤15 字概括该建议（如"仓位不宜低于5成"）。
   - 本场没有任何总量仓位建议时，输出**空数组** `[]`——**不要为了填满字段而把交易纪律或个股操作建议搬进来**。宁可这个字段是空的，也不要装错内容。
   - 引用要求：精准覆盖本块提出建议的语句，不重复引用盘面或宏观分析的依据。块间引用不得共享行号。
