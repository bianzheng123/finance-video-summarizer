【主动联想解码：音近候选为空时的出路】
音近候选（`[DATABASE]` 里确定性算出的同音/吞音候选）**为空不代表判不出**——ASR 错字常非严格同音（声母/韵母近似、吞字、英文谐音），不在候选里。此时按顺序尝试以下联想，每步都用上下文印证、放回原句通读验证，通顺才采信：
1. **上下文回填**：先搜 `[DATA]` 上下文（尤其同一话题段），该词的正确写法是否已在别处出现——直播会重复同一词，前面行已出现「军备竞赛」「Rubin」等就直接回填，不再猜。
2. **先懂句意、再反推词**：通读整句与相邻几句，先确定主讲人在讲什么，用句意约束反推该词应该是什么。
3. **错字部分锚定**：ASR 通常只错 1~2 个字，用「对的那几个字 + 整行读音」反推完整词（如「六佛化屋」→ 锚「六」「化」，反推「佛→氟」「屋→钨」→「六氟化钨」）。
4. **字数/音节对齐**：正确词字数通常与误识片段接近，排除字数差太多的候选。
5. **近音联想（含易混音）**：主动做声母/韵母近似联想，特别留意 ASR 高频易混音（zh/ch/sh、f/h、n/l、in/ing、an/ang，如 fó/fú、mín/míng、jiān/nián）。
6. **语义角色反推**：该词在句子里充当什么角色（「XX 崩了」→标的/公司、「XX 涨价」→材料/商品、「XX 机制」→制度/条款）。
7. **领域术语世界知识**：结合上下文联想该领域术语（金融「绿鞋」、半导体材料「六氟化钨」、存储「NAND」、GPU 架构「Rubin」），联想词必须贴合本行语境才采信。
8. **板块上下游联想**：遇到某板块/公司语境，联想该板块上下游的技术/原材料/产品术语（半导体/英伟达→GPU 架构与原材料、存储芯片→NAND/DRAM、半导体材料→六氟化钨、IPO 承销→绿鞋机制）。
9. **固定搭配/惯用语**：读不通的片段可能是某个固定搭配被误识（「军备竞赛」「绿鞋机制」「明年的指引」）。
10. **数字/字母/百分比格式**：数字、英文、百分比、型号混排是 ASR 高频出错区，联想正确格式（「V200」「30%」）。
11. **同段/话题共现词**：同一话题段相关词会共现（存储语境：海力士/美光/NAND），用共现词反推读不通的词。
12. **吞字/缺字识别**：片段是某多字词的缺字形态（「军备应」→「军备竞赛」），补全后验证。
以上联想能唯一确定正确写法 → 进「错词列表」（`依据`=`上下文`）；多个候选无法区分或都说不通 → 留疑似点（交给联网阶段）。

【黑话错别字：拆进两个列表】
「黑话错别字」= 字面错了、且它本身是圈内代称。这时**两条都要写**：
1. 错词列表：`标注` 用 `<err>原文错字</err>` 圈原文（如「韩王」），`修改的词`＝代称的正确写法（如「寒王」）。
2. 指代列表：`标注` 用 `<ref>原文错字</ref>` 圈**同一个原文错字**（如「韩王」——`[DATA]` 里只有错字，你圈不到改后的写法），`指代`＝正式名（如「寒武纪」），`依据`＝`数据库`。
系统会先按错词列表把原文改成正确写法、再按指代列表内联 `正确写法（正式名）`；指代那条的「原先的词」由系统自动映射为错词列表的「修改的词」，你无需、也无法在标注里写改后词。

【英文词当黑话（说英文因为中文词不让说）】
直播里主讲人常因某中文词敏感/不让说就改说**英文**，且别处口头点破（如「Bear 不是啤酒吗」）。判定读音接近英文词的片段时，先问：它的读音是否接近某个英文词，而这个英文词在 `[DATA]` 里被主讲人自己点破过等于某个中文词？若是、且映射到的是**普通词汇/日常词**，说明它只是绕开敏感词、**不是**某个读音相近的公司——本阶段给不出「普通词汇」结论，**留在疑似点**（不要硬套公司名，让联网阶段定案）。本阶段不联网，拿不准就留在疑似点。

【谐音+占位符隐藏敏感词（故意隐藏，不是错字）】
主播有时用「谐音字 + 什么/啥 + 数字」结构**故意隐藏**敏感指数/标的（如「磕什么50」=「科(什么)50」=「科创50」，主讲人不敢直说「科创50」就绕开说）。判据：**「什么/啥」夹在词中间是强信号**——ASR 不会把真实字听成「什么/啥」，出现「什么/啥」占位，几乎可断定是主讲人故意隐藏而非听错。处理：**走指代列表**映射正式名（`标注` 用 `<ref>磕什么50</ref>` 圈整个隐藏表达、`指代` 填正式名「科创50」、`依据` 填 `上下文`），**不改字面**（保留「故意隐藏」的可溯源痕迹）；不要把它当错词直接改成正式名。这与「说英文因为中文词不让说」是同一类，只是隐藏手法是「谐音+占位符」而非「说英文」。

【常见词作实体简称（zero-shot 上下文推理）】
常见词（「长江」「长城」「东方」等）在特定行业语境里可能是某公司/板块的**简称**，不要因为字面是常见词、读起来"通顺"就放过。判据：结合上下文行业线索词推理——如「长江」出现在存储/半导体语境（共现「存储/NAND/DRAM/颗粒/长鑫/美光/海力士」等），它就不是长江河流/长江电力，而是「长江存储」。处理：**凭上下文直接推理出完整实体名**，走指代列表（`标注` 用 `<ref>长江</ref>` 圈原文、`指代` 填「长江存储」、`依据` 填 `上下文`）；本阶段拿不准就留在疑似点交联网阶段。**这是 zero-shot 推理，靠常识 + 上下文，不依赖词表**——不要因为词表里没有这条映射就不敢判。

【硬性约束（防改坏字幕）】
1. **稳定表达保护**：改字面（进错词列表）前，先判断原词**字面本身是否正确**——若它是**字面正确、且结合上下文能确证为黑话/稳定口语/圈内代称**（如「老美」＝美国），说明它不是 ASR 误识，**不得改字面**；若需要映射正式名，走「指代列表」而非「错词列表」。
2. **只有 ASR 误识形态的替换能进错词列表**（读音相同或高频混淆、数字/字母按口语读音、个别音节增删）。以下两类**一律不得**进错词列表，留在疑似点：靠**删字**得到（「老美光」→「美光」）；换成另一个实体/含义的**自由推断**。
   - **粘字型边界错误 ≠ 删字**：当片段是「两个成分粘成一个」时，**不要整体删字**，而是**重新切分边界**，把正确的那段子串单拎出来作新判定对象——它是黑话/正式名 → 进「指代列表」（`标注` 用 `<ref>...</ref>` 圈切出的子串、`指代` 填正式名、`依据` 按来源填）；它是错字 → 进「错词列表」（`标注` 用 `<err>...</err>` 圈切出的子串）。`标注` 圈的子串只需是 `[DATA]` 该行原文的连续子串（子串即可，不必等于整个片段）。
   - **粘连片段断句：用「频次 + 并列结构」判断，别被局部语境带偏**：粘连片段常有多个切分可能（如「老美光」可切「老美 | 光」或「老 | 美光」），此时看两点：① `[TASK]` 里给出的「候选切分词全场频次」——高频词更可能是真实成分（「老美」全场 29 次、「美光」仅 2 次 → 「老美」更可能是成分，「光」另作消歧，而不是硬拼出「美光」）；② 前文的**并列结构**——「也崩了/也红了/同样/又」等并列标记前后的主语通常是同类实体（「棒子崩了 → 老美光也崩了」里「老美」与「棒子」并列，都是国家昵称），据此「老美光」=「老美 | 光」。同一黑话别名全场应消解到同一正式名，不要同一词在不同行消解成不同实体。
   - **两个实体名粘连**：片段是「两个已知公司/板块名各取一段粘在一起」（如「盛和阳光」=「盛和精微」+「阳光电源」）时，重新切分边界，把两个实体分别处理——各自是黑话/正式名则分别进「指代列表」（两个条目，各自 `标注` 用 `<ref>...</ref>` 圈切出的子串）。
   - **断句不清**：片段读不通但能看出是「主讲人说快了、两个词黏一起」（如「蓝箭长就是长江」=「蓝箭」+「长就是长江」），先按断句重新理解，再判断是否有 ASR 误识。
   - **语气词/口吃前缀粘连**：片段是「语气词/口吃/口头禅前缀 + 正常内容」粘一起（如「语宇树」=「语」+「宇树」、「那个股」=「那」+「个股」）时，**重新切分边界**：前缀单独切出进「嘴瓢」列表（`标注` 用 `<slip>前缀</slip>` 圈），后面的内容按性质处理——是实体黑话 → 进「指代列表」；是正确普通词/术语 → 保留不动。**不要整体圈成一个错字**，更不要因前缀是语气词就把后面的正确词误当错字改（「那个股」里的「个股」是正确词、不是「个股」的错字，不要输出「那个股→个股」）。
3. **多个互相竞争的假说、读音定不出唯一写法 → 留在疑似点**（交给联网阶段）。"没有拼音候选"≠判不出——还有 `[ANNOTATION]` 的 `行读音`。
4. **合法领域术语保护（禁止"更常见"式改写）**：一个词本身是**合法领域术语**（化学名/材料名/公司名/指数名/金融术语，如「碳酸钡」「MLCC」「铜价」），读音、字形都对得上、无 ASR 误识痕迹时，即使你"觉得"这个语境里更常见的应该是另一个相关术语（如 MLCC 语境里更常听说「钛酸钡」），也**不得**当错字改。「更常见」≠「说话人说错」——说话人可能说的就是那个不那么常见、但同样真实存在的词。改字必须同时满足「读音/字形对得上 + 换后词与换前词是同一含义层次」，禁止「我觉得应该是 X」式的换含义改写（「碳酸钡→钛酸钡」正是把两个都真实存在的化学名互相替换，是换含义、不是纠错）。拿不准就留在疑似点。

【字段规则】
- 三个 span 列表的定位统一用 `标注`：把该行原文（`[DATA]` 该行第二列正文）逐字节照抄，用 `<suspect>`/`<err>`/`<ref>` 标签只包目标 span，不带属性、不改其它字。系统据此定位，**无需输出出现序号**。
- `疑似点`：`标注` 用 `<suspect>片段</suspect>` 圈可疑片段；`初判类型` 用 `疑似错别字 | 疑似黑话 | 疑似黑话错别字`；`上下文线索` **只在仍需靠上下文消歧时才填**（疑似黑话/疑似黑话错别字/需线索门控的别名），确定性同音错字留空数组；`违和原因` 一句话说明为何仍可疑；`候选`（可选）＝判不出但能推断的最可能正确写法/实体名/方向，供下一阶段联网验证。
- `错词列表`：`标注` 用 `<err>错字</err>` 圈原文错词，`修改的词`＝正确写法；`依据` 填 `数据库`（查表）/ `拼音候选`（音近）/ `上下文`（纯推断）。
- `指代列表`：`标注` 用 `<ref>代词/黑话/绰号</ref>` 圈原文（黑话错别字圈**原文错字**，不是改后词），`指代`＝**实体名字数组**——一个黑话对应一个实体时填单元素数组，对应多个实体（一对多，如「易中天」＝新易盛、中际旭创、天孚通信）时拆成多个元素，**禁止用顿号合并成单个字符串**；`依据` 填 `数据库`（查表）/ `上下文`。
- 本阶段**不联网**，任何 `依据` 都**不允许填 `联网`**。

【跨片段同字词纠错提示】
`[TASK]` 中若出现「跨片段同字词纠错提示」清单，表示某原词已在**其他批次**被确证为错字并给出正确写法，且该原词在本批当前字幕中**仍出现、尚未修改**。请**自行判断**本批这些位置是否同样修改：能确定 → 进「错词列表」；不能确定 → 留在「疑似点」。这是提示而非指令，代码不强制、不拦截。

【禁止编造（可溯源）】
所有结论只能来自 `[DATA]` 原文与 `[DATABASE]` 映射。绝不允许凭世界知识补充字幕里没出现的标的、公司、事件。判不出就留在「疑似点」，这是正确的移交，不是失败。

【段落指代】
主播常在一个段落里用多种字面形态（中文/英文/谐音）表达同一个含义（如「beer」「啤酒」都指「熊市」bear）。当你识别出某组连续行在统一讲某个含义时，输出到 `段落指代` 数组：
- `rowID`：这组行的行号数组（升序、真实存在，逐字照抄 `[DATA]` 第一列）。
- `真实含义`：这组行统一表达的含义（段级解析结果，如「熊市」），≤20 字。
- `理由`：判断依据（≤40 字，如「beer 是 bear 谐音，下文慢牛对应熊市」）。

判定要点：只对"跨字面形态/跨行的段级统一含义"输出（单行单词的黑话解析走指代列表，不重复）；真实含义必须能从字幕上下文印证，禁止脑补；没有段级含义时输出空数组 `[]`。

【输出格式】
输出一个 JSON 对象，六个数组都必须出现，无内容给空数组：

{
  "疑似点": [
    {"rowID": 整数, "标注": "<suspect>可疑片段</suspect>该行其余原文逐字照抄",
     "初判类型": "疑似错别字 | 疑似黑话 | 疑似黑话错别字",
     "违和原因": "一句话", "上下文线索": ["线索1","线索2"], "候选": "最可能正确写法/实体名/方向（可选）"}
  ],
  "指代列表": [
    {"rowID": 整数, "标注": "<ref>代词/黑话/绰号</ref>该行其余原文逐字照抄",
     "指代": ["实体名字1", "实体名字2"], "依据": "数据库 | 上下文"}
  ],
  "错词列表": [
    {"rowID": 整数, "标注": "<err>错字</err>该行其余原文逐字照抄",
     "修改的词": "正确的词", "依据": "数据库 | 拼音候选 | 上下文"}
  ],
  "段落指代": [
    {"rowID": [整数, 整数], "真实含义": "段级含义", "理由": "判断依据"}
  ],
  "嘴瓢": [
    {"rowID": 整数, "标注": "<slip>嘴瓢片段</slip>该行其余原文逐字照抄", "违和原因": "一句话"}
  ],
  "事件描述": [
    {"rowID": 整数, "标注": "<event>事件短语</event>该行其余原文逐字照抄", "违和原因": "一句话"}
  ]
}

**标注写法硬规则**：
- `标注` 是 `[DATA]` 该行第二列正文的**逐字节照抄**，只在要标的 span 上包一个 `<err>`/`<ref>`/`<suspect>` 标签，标签**不带属性**、不包其它内容、不增删改任何字。
- 同一行要标多个 span → 输出多条 item，每条 `标注` 只圈一个 span。
- **不要输出出现序号**：标签已原地锁定位置，系统自己算 offset。

【输出前自查】
1. `[TASK]` 传给你的每一条疑似点都有了归宿：进错词列表 / 指代列表 / 留在疑似点 / （字面正确已解决）明确不输出？
2. 每条 `标注` 都是该行第二列正文的逐字节照抄，标签只包一个 span、不带属性、未增删改任何字？上下文线索都逐字出现在 `[DATA]`？
3. 命中黑话别名表的，都进了指代列表（`依据`=`数据库`），没有误当错字改字面？
4. 黑话错别字都**拆进了错词列表 + 指代列表两个列表**，且两个列表的 `标注` 都圈**同一个原文错字**？
5. 错词列表只收 ASR 误识形态的替换，没碰稳定表达、没靠删字、没换含义、没碰立场词（多空/买卖/涨跌）？
6. 没有任何 `依据` 填了 `联网`？
7. 判不出的都留在疑似点，没有硬猜？
8. 同一行多处标注时，每条 item 只圈一个 span，没有漏标、没有重复标？
9. 疑似点牵连的相邻文本有问题，也一并上报了（新增疑似点）？
10. 合法的领域术语（化学名/材料名/公司名/指数名等）没有被"我觉得更常见的是 X"式地误改？（「碳酸钡」不得改成「钛酸钡」）
11. 语气词/口吃前缀 + 正常内容的粘连有没有正确切分（前缀进嘴瓢、后面内容单独处理）？「什么/啥」占位符的隐藏黑话走了指代列表（没改字面）？常见词简称有没有结合行业语境推理出完整实体名？
